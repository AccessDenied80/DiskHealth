# DiskHealth — дизайн застосунку моніторингу дисків (аналог SSD Reporter)

Дата: 2026-11-01

## Навіщо

Користувач хоче завжди знати стан **усіх** дисків свого Mac (внутрішніх і зовнішніх)
і **отримувати попередження**, коли диск починає деградувати — до того, як втратить дані.

## Цілі

- Нативний macOS-застосунок на Swift/SwiftUI, що живе в рядку меню.
- Показує всі фізичні диски, які бачить `smartctl`: внутрішні NVMe/SATA, зовнішні
  (USB/Thunderbolt — наскільки дозволяє міст диска).
- Для кожного диска: модель, серійний номер, прошивка, обсяг, тип (NVMe/SATA/USB),
  SMART-статус (PASSED/FAILED), знос (%), температура, записано/прочитано (ТБ),
  години роботи, кількість увімкнень, лічильники помилок (media errors, critical
  warning, reallocated/pending sectors, CRC errors, unsafe shutdowns).
- Фонове опитування з налаштовуваним інтервалом (за замовчуванням 30 хв) + кнопка
  «Оновити зараз». Автоопитування при підключенні нового диска.
- Історія значень (знос, записані ТБ, температура) з простими графіками.
- Системні сповіщення macOS при:
  - SMART FAILED або ненульовий NVMe critical warning;
  - зносі ≥ порогів (за замовчуванням 80% і 90%);
  - температурі ≥ порогу (за замовчуванням 60 °C);
  - зростанні лічильників помилок / перепризначених секторів порівняно з попереднім опитуванням.
  Кожне попередження надсилається один раз на подію (не спамити при кожному опитуванні).
- Налаштування: інтервал, пороги, запуск при вході в систему.

## Не-цілі

- Розмітка/форматування дисків, бенчмарки швидкості, запуск SMART self-test (можливо пізніше).
- Підтримка iOS / Windows.
- Публікація в Mac App Store (sandbox не дозволить запускати `smartctl` з IOKit-доступом).

## Анти-цілі

- Хибні тривоги, що привчають ігнорувати сповіщення.
- Вимога ставити щось окремо (brew тощо) — застосунок має працювати «з коробки».
- Потреба в паролі адміністратора для звичайного читання SMART.

## Обмеження та рішення

- **Збірка без Xcode** (рішення Claude): Swift Package Manager + Command Line Tools
  (Swift 6.2 вже є). Скрипт `build-app.sh` збирає executable і пакує в `DiskHealth.app`
  (Info.plist, `LSUIElement=true`, ad-hoc підпис `codesign -s -`). Xcode не обов'язковий,
  але пакет відкривається в ньому.
- **`smartctl` вбудовано в `.app`** (рішення користувача): бінарник smartmontools 7.5
  копіюється в `DiskHealth.app/Contents/Resources/smartctl`. Залежить лише від системних
  фреймворків. Поточний бінарник — x86_64; для Apple Silicon у майбутньому потрібна
  universal-збірка smartmontools з сирців (поза межами v1, але скрипт має це передбачити).
- **Джерело даних**: `smartctl --scan-open --json` для переліку, далі
  `smartctl -x --json=c <device>` для кожного диска. Розбір JSON через `Codable`.
  На macOS читання SMART внутрішнього NVMe працює без root.
- Зовнішні USB-диски: SMART доступний лише якщо USB-міст підтримує SAT; інакше диск
  показується з позначкою «SMART недоступний» (дані з `diskutil` — модель, обсяг).
- Мінімальна macOS: 13 (MenuBarExtra, Swift Charts).
- Сповіщення: `UserNotifications`. Історія: JSON-файл у
  `~/Library/Application Support/DiskHealth/` (без Core Data — простіше).

## Інтерфейс

- Іконка в рядку меню: колір/символ за найгіршим станом серед дисків
  (зелений — OK, жовтий — увага, червоний — критично).
- Вікно MenuBarExtra (`.window` стиль): список дисків-карток з ключовими показниками
  та індикатором здоров'я; клік — деталі диска (усі атрибути + графіки історії).
- Вікно налаштувань (Settings scene).

## Оцінка здоров'я

- Критично: SMART FAILED, critical warning ≠ 0, знос ≥ 90%, media errors зросли.
- Увага: знос ≥ 80%, температура ≥ порогу, reallocated/pending > 0, CRC errors зросли.
- OK: решта.
- «Здоров'я %» у UI = 100 − знос (для NVMe `percentage_used`; для SATA SSD — з
  атрибутів 231/233/177/202 залежно від виробника, якщо доступні).

## Залишено на розсуд виконавця

- Точна структура модулів, назви типів, вигляд карток.
- Як виявляти підключення дисків (DiskArbitration або періодичне `--scan`).
- Формат зберігання історії та її обрізання (напр., останні 365 днів).
- Unit-тести парсера на зразках JSON із реального `smartctl`.
